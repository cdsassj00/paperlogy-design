### 템플릿 모드 요약
- `templates/references/catalog.json`에서 category·original_page·`text_slots`를 보고 고른다. 미리보기는 `templates/previews/`.
- 실행(스킬 폴더 기준):
  ```bash
  pip install -r templates/requirements.txt
  python templates/scripts/use_template.py --id paperology-050 --out NEW.pptx
  python templates/scripts/use_template.py --id paperology-050 --replace changes.json --out NEW.pptx
  ```
- `changes.json`은 shape ID → 바꿀 문자열. 모르는 ID는 실패하고, 빠진 슬롯은 원문 유지.
- 한 번 실행에 1장. 여러 장을 합칠 때는 PPTX 관계(rId)를 다시 잇는 병합기를 쓴다. ZIP/XML을 그냥 이어 붙이지 않는다.
- **글꼴:** 템플릿 팩에는 글꼴이 없다. 이 스킬의 `assets/fonts/ttf/`(Paperlogy·Pretendard)를 설치하거나 함께 전달한다.
- 한계·검증 기록은 `templates/references/PORTABILITY.md`. 원본 사진·로고는 이미지로 남으며 재배포 권리는 별도다.
# Paperlogy Design

원본: `D:\보고서\페이퍼로지_2024강의통합본.pptx` (611장, 61 PRINCIPLE). 원본의 사진·문구는 복제하지 않고 **원리·수치·구조**만 쓴다.

## 핵심 DNA 12 (모든 장표에 적용)

1. **생각 → 글 → 디자인.** 5:3:1:1(생각·글·PPT·리뷰). 장표를 열기 전에 장당 한 문장 원고부터 쓴다.
2. **원슬라이드 원메시지.** 한 장 = 한 문장. 담을 게 많으면 페이지를 쪼개 순차 공개한다.
3. **형용사 → 숫자.** "많이 늘었다" 대신 "46% 상승". 숫자는 히어로 크기로.
4. **제목 굵기 혼합.** 키워드 ExtraBold(800) + 조사·서술어 Regular(400)/Light(300). Ctrl+B 금지, 굵기 패밀리로. 한글 제목 속 영문 키워드는 `.k-en`(Montserrat).
5. **컬러 마침표.** 제목 끝 `.`만 컬러(`--dot`). 덱 전체의 서명. 업종색 덱에서도 서명 핑크를 유지하려면 `--dot:var(--pink)`.
6. **타이틀 크기 이분법.** 큰 타이틀 38–42pt(≈52–56px)=역동 / 작은 타이틀 ≤25pt(≈33px)=품격. 둘 다 30자 이하. 어절 중간에서 줄을 끊지 않는다.
7. **자간을 조인다.** 제목 −0.06em, 본문 −0.04em, 행간 1.1–1.2(제목). 덩어리감.
8. **회색이 컬러의 열쇠.** 활성 1개만 흰색/컬러, 나머지 #333–#5A5B60(`data-dim`). 사진도 배경 흑백 + 주인공 컬러.
9. **액센트는 덱당 1개(+보조 1).** 브랜드색 → 없으면 업종 연상 테마: `data-theme="blue"`(IT) / `red`(식품) / `mint`(건강·친환경) / `yellow`(유통). 기본 = 핑크.
10. **배경이 막히면 그라데이션.** 검정 + 상단 오로라 / 하단 오로라 / 성운 + 행성 림. 색은 테마의 `--glow1~3`을 따른다.
11. **못을 박아 안정감 (키노트 카드·사진).** 네 모서리에 ┏┓┗┛ / + / ○ / A B C D.
12. **매직넘버 3 + 순차 공개 (키노트).** 항목은 3개, 한 장에 다 띄우지 말고 하나씩 밝힌다(워드스택 K04 복제).

## 강의·발표 덱 필수 게이트 (어기면 납품하지 않는다)

에세이·원고·교안을 받아 덱으로 만들 때 가장 흔한 실패는 **"좋은 원고를 같은 보고형 틀(R01)에 문단째 붓는 것"**이다. 렌더 검사(넘침·겹침)는 이걸 통과시킨다. 아래 네 관문을 순서대로 지난다.

1. **원고 파일을 먼저 만든다 (`outline.md`).** 장마다 한 줄: `- 메시지 한 문장(40자 이내) | 아키타입 | 기승전결 위치`. 원고의 문단은 장표가 아니라 **발표자 메모**로 간다. 이 파일 없이 빌드를 시작하지 않는다.
2. **기승전결을 원고에서 확인한다.** 질문(기) → 전개·근거(승) → 반전·전환(전) → 결론·행동(결). 반전 장과 결론 장이 어디인지 원고에 표시한다. 같은 주장을 다른 말로 반복하는 장은 지운다.
3. **아키타입을 섞는다.** 메시지·전환·질문 = K(K02/K05/K06/K09/K10…), 근거·표·실습 = R. 강의 덱은 한 레이아웃 ≤ 35%, 같은 레이아웃 연속 ≤ 3장, 20장 이상이면 8종 이상, R* ≤ 50%. 검정만 계속되면 `paper`/`holo` 장표로 명암을 끊는다. 내용에 맞는 아키타입이 없으면 `Deck`의 기본 부품(text·rect·tag·card)으로 **새 장표를 그린다** — 억지로 R01에 넣지 않는다.
4. **검사 두 개를 모두 통과한다.**
   ```bash
   python scripts/render_pptx.py deck.pptx out --check      # 넘침·겹침·글자 크기·빈 띠
   python scripts/deck_lint.py deck.pptx --outline outline.md  # 레이아웃 반복·문단 붙여넣기·평균 글자량·메모
   ```
   그다음 `out/contact.png`와 **장표 5장 이상을 원본 크기로 직접 열어** 본다. "같은 장표가 이어진다", "문단이 보인다", "제목이 문장이 아니라 문단이다" 중 하나라도 보이면 고친다. 검사 PASS는 출발선이지 완성이 아니다.

- slide-density(빈 띠 ≤12%)는 **보고형 R* 장표에만** 적용한다. 키노트 장표를 글자로 채우는 근거로 쓰지 않는다.
- 사용자가 준 문장은 살리되, 장표에는 **그 문장의 핵심 한 줄**만 올린다. 나머지는 메모와 배포물로 보낸다.

## 워크플로

0. **slide-density 규칙 연동** (사용자 전역 규칙): 보고형(R*) 장표는 빈 띠 ≤12%를 강제한다. 키노트(K*·C*) 장표는 slide-density의 '표지·섹션·히어로 예외'에 해당한다. 의도적으로 여백을 쓰되, 균형은 육안으로 검토한다.
1. **원고 먼저.** 메시지를 장당 1문장으로 쓰고 덱 HTML 상단 주석(`<!-- 원고: 01 … -->`)에 남긴다. 구조 선택:
   - 사내 보고 → **PREP**(결론→이유→예시→결론). 3요소: 감성보다 논리, 디자인보다 정렬, 결론부터.
   - 사내 제안·품의 → **PREP 골격 + 설득형 감정선**. 결론(요청)을 먼저 말하고, 근거 장에 위기감·납득·결단을 싣는다.
   - 외부 설득 → **설득형 4단계**: 문제발견(+위기감) → 원인파악(+납득, 숫자) → 해결(+결단) → 결론(+확신)
   - 챕터 오프너 → 매니페스토(짧은 선언 연속) → 내로우다운(개요→상세)
   - 각 장에 So What?/Why Not Yet?를 붙여 정보가 아닌 의견으로 끝맺는다.
   - 실데이터가 없어 만든 수치는 반드시 `.note`(하단 중앙 각주) 또는 리포트 푸터에 **"※ 예시(샘플) 수치"**로 표기한다.
2. **모드·테마 결정.** KEYNOTE(발표형) / REPORT(보고형) / 혼합. 테마는 브랜드색 또는 업종 연상으로 정한다. 표지 제목을 사용자가 주지 않았으면 후보 2–3개를 제시해 확인받고, 이미 줬으면 그대로 쓴다.
3. **아키타입 매핑.** 메시지마다 `references/layouts.md`의 C01–C03(표지·엔딩·목차), K01–K17, R01–R04 중 하나를 고른다. 덱 길이별 리듬 규칙을 따른다(10장 이하는 축약형).
4. **빌드.** `assets/paperlogy-deck.html`을 작업 폴더에 `deck.html`로 복사하고, 필요한 `<section>`만 남겨 복제·수정한다.
   - 테마: `<div class="deck" data-theme="…">`. 커스텀 브랜드색은 `:root`의 `--accent, --accent-on-dark, --accent2, --dot, --glow1~3`를 **함께** 바꾼다. 검정 위 글자는 반드시 밝은 변형(`--accent-on-dark`)을 쓴다.
   - 라이트 장표는 `class="slide paper"`. 보고형 부품: `.rp-card .meter .kpi .bars .roadmap .rp-conclusion table.rp`.
   - **폰트 = Paperlogy(제목·디스플레이) + Pretendard(본문·표·각주)**. 둘 다 `assets/fonts/`에 번들(OFL 1.1). 덱을 다른 PC·오프라인에서 열 수 있게 `assets/fonts/woff2/*`를 `deck.html` 옆 `fonts/` 폴더로 복사한다. PPTX는 `assets/fonts/ttf/`를 설치하거나 함께 전달한다.
   - 푸터 `COMPANY NAME`은 회사·팀명으로 교체한다.
   - 사진은 `style="--img:url(파일)"`로 넣는다. 없으면 톤 플레이스홀더를 유지한다.
   - 작업 폴더에는 `deck.html`과 사진만 남기고 임시 조각 파일은 지운다. PPTX가 필요하면 `references/pptx.md`를 본다.
5. **렌더·검증.**
   ```bash
   python ~/.claude/skills/paperlogy-design/scripts/render_slides.py deck.html out --check
   ```
   - 각 장 PNG와 `out/contact.png`를 만든다. 긴 Windows 경로도 처리한다(로컬 HTTP 서빙).
   - **FAIL 조건:** 11px 미만 글자, 가장자리 침범, 텍스트 블록 겹침·붙음, 높이 고정 박스 넘침, R*의 slide-density 채움 미달.
   - **WARN 조건:** 판독 위험 대비. 일부러 회색 처리한 텍스트는 `data-dim`으로 제외한다.
   - FAIL이 나면 고치고 다시 실행한다. PASS가 나와도 `contact.png`를 직접 열어 균형·위계·대비를 눈으로 확인한다. 스크립트는 장식(구체·사진)이 글자를 가리는 것을 잡지 못한다.
   - PPTX면 `scripts/render_pptx.py deck.pptx out --check`, 그리고 **항상** `scripts/deck_lint.py deck.pptx`(보고서는 `--report`)를 함께 돌린다. 둘 다 PASS여야 납품한다.
6. **자가 점검.** `references/principles.md` 맨 아래 체크리스트(공통·K·R)를 통과시킨다.

## 리뷰 모드 (기존 장표 진단)

사용자가 장표·PPT를 "페이퍼로지 관점으로 봐 달라"고 하면 다음 순서로 진행한다.
1. 장표를 렌더해 본다.
2. DNA 12 + 체크리스트 위반을 원칙 번호(예: P40, P26)와 함께 지적한다.
3. 장별 Before/After 수정안을 제시한다. 가능하면 해당 아키타입으로 재구성한 HTML로 보여 준다.

## 금지

- 외부 템플릿을 그대로 쓰기
- 한 장에 차트 여러 개
- 형용사로 끝나는 근거
- 같은 크기 항목 나열 → 빅·미디엄·스몰로 위계를 준다
- 강조 기법 혼용
- 맨 스크린샷 → 목업에 넣는다
- 톤이 안 맞는 클립아트
- 가짜 볼드
- 한글 폰트로 영문 디스플레이
- 검정 배경 위 어두운 액센트 글자(대비 붕괴)
- 감성 문장을 본문 데이터 장표에 넣기 → 감성은 표지·간지·엔딩에만
